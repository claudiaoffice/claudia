# D177 · An object is a shared body plus an app-specific anchor, and everything except the anchor is written once in `claudia_core`

**An object is a shared *body* plus an app-specific *anchor*, and everything except the anchor is written once in `claudia_core`.** `ObjectBody` (id, kind, w, h, style, text, shape, image, imported, rotation, snap) is the same dataclass in all three apps; `Anchor` is a protocol with `kind`, `container` and `to_data`, implemented per app as `SlideAnchor(slide, x, y)` in creates, `CellAnchor(sheet, row, col)` in computes and `BlockAnchor(block, offset)` in composes. `VisualObject` is the pair; `ObjectModel` is the mixin holding objects, their stacking order, the shape outlines and the image assets, with `containers()`, `check_anchor` and `anchor_from_data` left to the app. The whole object command family moved to core as `core.*`: `DefineShape`, `ForgetShape`, `DefineImage`, `ForgetImage`, `AddObject`, `RemoveObject`, `MoveObject`, `ResizeObject`, `RotateObject`, `SetText`, `SetSnap`. An anchor crosses the log and the wire as plain data and is read back only by `ObjectModel.anchor_from_data`, so a command stays what the kernel requires — immutable plain data, buildable without a model — and the one app-specific door is the same shape as the existing `region_from_data`. On the wire an object is now `{id, kind, w, h, style, text, shape, image, imported, rotation, snap, anchor}` in every app, with only `anchor` differing; `ObjectSet` and `ObjectsChanged` lost their `slide`/`sheet` field in favour of one `container`. Renaming the commands' `kind` makes logs written before this round unreadable: `CommandRegistry` keys upcasters by `(kind, schema)` and cannot alias one kind to another, and **the owner chose to break old logs** rather than add an aliasing mechanism, this being pre-release. The old per-app upcasters for `creates.AddObject` schemas 1 and 2 went with them. State schemas: creates 4→5, computes 3→4, composes 3→4 (a snapshot is only a cache, D15, so these rebuild from the log). `rotation` is persisted and validated (0–359) and has its own command, but no client surface yet.

**Notes.** The owner's request, after this chat established that the `claudia-core` `assets` and `css` modules were already shared while `DefineImage`/`ForgetImage` sat duplicated line-for-line in creates and computes, and that the anchor was the only genuine divergence. Four questions settled by `AskUserQuestion` before any code: break old logs (over a kind-alias mechanism or thin per-app subclasses); the full style alignment below; composes' anchor; the shape vocabulary. Deduplicated along the way: `insert_object`, `delete_object`, `replace_object`, the per-container stack, `objects_on`, `check_object`, `_check_visual`, the image define/forget pair, `ObjectSet` and `ObjectsChanged` all existed twice and now exist once. `claudia_core.shapes` took the shape *format* (`ShapeDefinition`, `parse_shape`, pure, no I/O, so core stays I/O-free and all three apps can hold a shape); `ShapeLibrary`, which reads folders from disk, stayed in `claudia_creates.shapes`. Command labels and summaries took creates' wording ("Add text box", "Edit text", "Snapped an object to the grid") over computes' lower-case phrasing, since creates' were the ones a person had actually seen. Each app package re-exports the core object API so that it still names everything it can do.
