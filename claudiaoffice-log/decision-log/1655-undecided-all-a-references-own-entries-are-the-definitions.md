# D1655 · A reference's own entries are the definition's; the purpose chooser of a column is not a menu

**The context menu of a reference is Show As ▸ (Number · Text · Number and Text · Page · Name, the current one ticked), then Go to Target and Remove Reference, in the workbook (Context menus, rows 53 and 54) and in the definition, in all three apps. They have no key: context-only entries go without one (D1614). Wrap Text… stays one entry of the definition whose modes and Gap… the page opens as its choices (D1654); the workbook's row describes that submenu already. The purpose of a table's column in computes is chosen in a popover of the column's header chip, a control and not a context menu, so it gets no row.**

**Notes.** UX-96 left the choice to the owner; this is the proposal it was fixed with, to be confirmed. The reference menu opens in composes only: creates' text boxes and computes have the menu in their definitions but no place that opens it yet.
