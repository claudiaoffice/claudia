# D1600 · A menu shows what fits; whether the rest is hidden or greyed is one switch per reason

**Every menu entry, in the top menus and in the context menus, is shown only where its action fits: the person's role, what the server can do, the client, the document's state, the selection, and whether the ai can really answer (D1601). What does not fit is hidden or greyed, set per reason, not per app: the owner wants to try hiding everything that does not fit and compare it with greying, so both stay one switch away.** There are no entries that never hide, Undo and Paste included; an entry's own setting can still keep it (D1606).

**Notes.** The usual convention (GNOME, macOS) greys what is unavailable for a moment and hides what never applies; the owner chose to try the radical version, hiding for every reason, knowing that the menus then change shape while one works, and to judge by use. D361 stands: every client still defines every entry; whether it is shown is decided at run time, by the same rule in every client. Precedents: the desktop client's short menu on the front page hides what does not fit there (`window.py`), and D209 leaves out style controls a thing cannot have. The question of a viewer's Replay History… (greyed today while History and Chat is not, D1261) is one of the first things the trial settles.
