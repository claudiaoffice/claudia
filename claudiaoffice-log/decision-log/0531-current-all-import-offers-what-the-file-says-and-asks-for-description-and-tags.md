# D531 · Importing a file asks for description and tags, offering what the file itself says

**The import dialog has two optional fields, description and tags, between Name and the person's own name and password. The upload answer carries what the file says about itself: Dublin Core `description` (`subject` if there is no description) and the keywords of `docProps/core.xml` (Word, Excel, PowerPoint; comma or semicolon) and of `meta.xml` (OpenDocument; one `meta:keyword` each). The fields start with that and say "from the file"; nothing is sent before Open. What does not fit the limits of D530 is cut or left out, never refused; a part larger than 64 kB, with a DOCTYPE or not XML says nothing; the boilerplate of the writer libraries ("generated by python-docx", "generated using python-pptx") is not offered. A Claudia file goes in as it is: its own description and tags are shown read-only and change afterwards with Details…. The server checks the text before anything is made, so a tag that does not fit costs nobody a half-made document; the answer says `described`.**

**Notes.** Written back on export (Word `dc:description`, `cp:keywords`; OpenDocument `dc:description`, `meta:keyword`) is the other half of the mock-up's table D and is not built yet: see the story E5.18. Observed while building: the docx and pptx writers keep the template's author fields ("python-docx", "Steve Canny") in core properties; they are not read but should be replaced by the document's own info (as D411 does for OpenDocument).
