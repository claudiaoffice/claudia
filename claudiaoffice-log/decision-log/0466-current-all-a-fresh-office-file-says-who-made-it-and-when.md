# D466 · A fresh Office file carries the properties of the document

**The three Office writers stamp `docProps/core.xml` and `docProps/app.xml` of the package they write from the
`DocumentInfo` of the log (D411): title, creator, created, last modified by, modified. What the log does not know is
left out, not invented. The application is "Claudia".**

**Notes.**

* *Why.* python-docx, python-pptx and openpyxl start from a template package: its author was "python-docx" (or
  "Steve Canny"), its date 2013, its title "PowerPoint Presentation". A person who downloads a document sees the wrong
  author in Word's file properties and in every file manager (IEW-02). odt, ods and odp had had the right ones since D411.
* *Where.* `claudia_opc_io.properties` (`stamp_core_properties`, `stamp_package`, `utc_second`) works on the parts of an OPC
  package; `claudia_odf_io.stamp_office_meta(data, info)` is the call the three writers make (`text_to_docx(..., info=)`,
  `workbook_to_xlsx(..., info=)`, `slides_to_pptx(..., info=)`), and `odf_date` is `utc_second` with an error type.
  The server passes `document_info` of the log on a fresh write; a patched file keeps what it has, as it keeps
  everything else (D217).
* *Dates* are W3CDTF in UTC to the second (`2026-11-17T09:30:00Z`), as the standard asks for core properties.
* *What is removed.* Elements of the template that are not the document's (`dc:description` "generated by python-docx",
  `cp:keywords`, `cp:category`, `cp:lastModifiedBy` the template's) are dropped when the log has nothing for them.
* *Not here.* A document's tags and description (D414) have a place in core properties (`cp:keywords`, `dc:description`);
  they are not written yet (they are in odt/ods/odp as user-defined properties).
