# D413 · `claudia-computes-io` reads and writes ods: a table is a sheet, a cell with content is a cell, and an edit is patched onto the original bytes

**`workbook_to_ods`, `ods_to_workbook`, `apply_edits_to_ods`, `ods_import_losses` and `ods_export_losses` are the ods counterpart of the xlsx functions of D220.** A `table:table` is a sheet (`s1`, `s2`... by its place, named by `table:name`); a cell with a value, a text or a formula is a cell, constants as `{"t": int|float|text|bool|formula}` like for xlsx. **Repeated rows and cells (`table:number-rows-repeated`, `table:number-columns-repeated`) are expanded: every position is a cell of its own on the way in, and an edit splits the run where it has to** (a thousand empty rows after the data cost nothing; a run that holds content is capped by `_MAX_CELLS` = 2 000 000, a bigger file is refused rather than read). Covered cells (inside a merge) are not cells. Dates and times become Excel serial numbers (epoch 1899-12-30; a time is a fraction of a day) with the loss `date`; a percentage or currency is a number (the look is lost); an error value without a formula is its text with the loss `error-value`; an empty string is an empty cell; a whole number is an `int`. After the cells are in, the model calculates them (`_calculate_loaded`), so what a sheet shows is what the model computes, and the file's cached value is only what the file says.

**What is not in the model is reported, not dropped silently.** Import: `formula:<reason>` (a formula with no Excel counterpart is kept as its cached value, D414), `date`, `error-value`, `look`, `merge`, `comment`, `formatting`, `link`, `chart`, `picture`, `object`, `shape`, `conditional-format`, `protection`, `hidden-row`/`hidden-column`, `layout` (column widths, row heights, styles), `out-of-range`, `named-range`, `validation`, `filter`, `pivot-table`. Export: `formula:<reason>`, `chart`, `object`, `layout`.

**`apply_edits_to_ods(original, baseline, current)` patches the original bytes (D401).** What it rewrites: the cells whose content differs, and **formula cells whose content is the same but whose computed value changed because something they depend on changed** (the `table:formula` stays, only the value attributes are rewritten, so a cell shows the right number in a program that does not recalculate, D408). A rewritten cell is the old cell with its value attributes and text replaced, so its look, comment and merge stay. Rows past the end of the file are appended after the last row's container, missing columns are declared with `table:table-column`; sheets can be added, removed and renamed. With nothing changed the result is the original bytes; everything not edited, in `content.xml` and in every other part (charts, pictures, styles, settings), is byte for byte what it was. **It raises `UnsupportedEdit`** for sheets in another order, an edit of a cell inside an array formula (it is read as its values, not editable), and a baseline that is not what the file holds. Removing or renaming a sheet reports `stale-reference` where something the model does not hold (a chart, a named range, a validation) still names the old sheet: the reference is not rewritten.

**Known limits, accepted for now.** (1) **A formula that cannot be translated keeps its formula in the file and its value in the model: if an edit changes what it depends on, the cached value in the file is stale until a program recalculates it** (LibreOffice does on load, as the check of `scripts/odf_libreoffice_check.py` showed; the library's fixture keeps such a formula on cells no edit touches so the check can compare every cell). (2) Cell styles, column widths and row heights are not mapped (D407). (3) Stale references as above. (4) XLOOKUP and XMATCH are written as `COM.MICROSOFT.XLOOKUP`/`.XMATCH`, as OpenFormula names them; not verified in a LibreOffice newer than 24.2.

**Notes.** `NS` gets the `of` namespace and `calcext` (the file must declare `of`, or LibreOffice reads every formula as `Err:510`); `XmlPart.replace` takes several replacements; a copied cell is built as a fresh element with the full namespace declarations so no `ns0:` prefix appears. `export_office` of the spreadsheet app takes `"ods"` and answers with `losses`; the Export dialog lists it; the metadata comes from the log (D411). Checked against LibreOffice 24.2.7: a file made from a model and every edited fixture convert to xlsx and **every cell has the value the model computes** (`scripts/odf_libreoffice_check.py` now covers odt, odp and ods: 31 of 31; the CI job installs Writer, Impress and Calc). The test-document library gets four ods entries: three written by LibreOffice (converted from the xlsx fixtures: cells and a formula, a chart, a picture) and one made by hand (repeated rows, merged title, comment, date, union formula, error cell, named range, validations). `ods` is done; with it the three formats of D408 are.
