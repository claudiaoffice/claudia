As a user, I want shapes to be small JSON files in a folder that I can add to, so that the collection is extensible without changing the program.

**Acceptance:** format version 1 with `format`, `id`, `name`, `path` (absolute `M`, `L`, `C`, `A`, `Z` in a 100×100 box with a strict grammar) and optional `aspect` and `text_area`, with invalid files skipped and listed at start-up naming the offending part; a library is a folder, the built-in one always loaded and `--shapes DIR` adding more, a later folder replacing a shape of the same id; **a document embeds the definitions of the shapes it uses** and opens without the library; the insert bar lists the library's shapes by name.

**Status evidence:** all of it is built and tested with fixture files. Known follow-ups, which are E10.13 rather than this story: no way to add a shape from the web app (the folder is on the server), no shape categories, and no shapes with several paths or fill rules.
