As a user, I want to style cells, ranges, rows and columns with named styles that use CSS table properties.

**Acceptance:** a cell carries a style name, settable for a cell, range, row, column or sheet default, layered in a fixed order, and the dialog says where a cell's look comes from; properties from the allow-list; style ranges stored as runs or ranges, not per cell, moving with row and column edits, measured with a million styled cells; the grid draws from the computed styles without an element per cell; export of the named styles to xlsx and ODS is E6.18 (D314).


**Status evidence:** the backend is built (styling-suite plan, step 1.6): `claudia_computes.cellstyles` — style ranges per sheet for the `box` and `words` slot of a cell, in four layers by shape, non-overlapping inside a layer, moved by row and column inserts and deletes and put back by their undo, in snapshots; `SetCellStyle` with regions and kind checks; the built-in Header, Input, Result and Note (D313); `CSS_VERSION` 3 (`vertical-align`, `white-space`); on the server, cells are a target of `apply_style`/`deviate` (both slots by default, D311) and `cell_styles`/`cell_style_at` read them. Tested against a cell-by-cell model with random sequences, and with a million styled cells as a performance guard. **Not done:** the grid drawing them and the menus for cells (plan step 2.6); xlsx and ODS (E6.18, D314).
**Notes:** Settled in D307: a cell has a Box slot and a Paragraph slot (D304), the allow-list goes to `CSS_VERSION` 3 (`vertical-align`, `white-space`), style ranges are layered per sheet and set by a `SetCellStyle` command. Both slots filled by one style (D311); the five built-in cell styles of D313. **xlsx export and import of cell styles are not part of this card** (D314, a later round); ODS likewise. Built after E1.11 and E5.14. Row heights and column widths are sheet layout, not part of this card (D135, E6.16). Depends on E1.10, E6.1, E6.3.
