As an analyst, I want to drop fields on rows, columns and values and see a summary table of my data, so that I can answer "how much per region and quarter?" without writing a query, and still see the query when I want to learn or change it.

**Acceptance:** a pivot is a named definition over a table, named range or query result (D620); it compiles to SQL on the existing read-only engine, so the SQL shown is the SQL run (D621); step 1 supports one row field, one column field, values (sum, count, average, min, max), filters and grand totals; the grid is values with roles for styling, in Excel's compact layout, and the words come from the client for i18n (D622). Step 2 puts a pivot into a workbook: a `PIVOT("name")` formula in its first cell, the definition kept by name, live recalculation (D623, D626), one history step to make, change or delete one. Step 3 is the server API (`pivots`, `define_pivot`, `update_pivot`, `delete_pivot`, `pivot_sql`, `pivot_to_sql`; the assistant gets the same methods). Step 4 is the web client: the field panel and dialogs of the approved mocks (D624, D627). Step 5 is files and help: a pivot is written to and read from ods and xlsx (D625, D628) and the topic `computes.pivot-tables` explains it in English and German. Later steps: the field panel in the GTK client's own widgets if it ever stops showing the web page, `GETPIVOTDATA` (D481).
