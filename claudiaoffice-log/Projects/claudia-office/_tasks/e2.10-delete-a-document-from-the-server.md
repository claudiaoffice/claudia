As an owner, I want to remove a document from the server entirely, so that a document nobody wants kept any more does not just sit there.

**Acceptance:** only an owner may delete; the document's file and any server-side bookkeeping about it are gone; everyone who had it open is told at once and returned to their document list; deletion cannot be undone and the confirmation says so.

**Notes:** Built directly as a `DeletableDirectory` capability of `SealedDocuments`, alongside leave and transfer-ownership, rather than as its own story up front.

**Status evidence:** built — `delete_document` on the server, `file.manage.delete` in the Manage menu (web and GTK), an `ephemeral` `document_deleted` push that closes every other open connection to it. **Not done:** nothing server-side; the lightweight demo backends (`ScryptDirectory`/`FileDirectory`) do not implement it, matching how they already skip `RecoverableDirectory`.

**Checked against the code, 2026-11-17 (`main` at `6814bac`).** The story's own status evidence says it is built, and the code agrees: `delete_document` (`sealed.py`, `auth.py`), File ▸ Manage ▸ Delete (`file.manage.delete` in all three apps' menus), the `document_deleted` push (`base-session.ts`); tests `test_server_membership.py`, `session.test.ts`. A stale second "Status evidence: nothing in the tree" and a line copied from E2.9 were removed.
