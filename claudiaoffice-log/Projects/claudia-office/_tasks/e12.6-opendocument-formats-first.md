As a user and as a public organisation, I want to import and export ODT, ODS and ODP.

**Acceptance:** one shared ODF layer for packaging, styles, embedded images and metadata, with app-specific mapping in E9.5, E6.9 and E10.3; export and import for all three apps come before the Microsoft formats; each import lists what could not be kept and each export is checked by opening it in LibreOffice; **the native format stays** and open-format exports contain the current state only, which the dialog says; named styles map to named ODF styles and templates to master pages, with every export listing what could not be mapped.

**Notes:** Whether public administrations require ODF is to verify per country.

**Status (2026-11-11), the `openoffice` branch:** the shared ODF layer exists (`claudia-odf-io`, D401: packaging with the `mimetype` rule in `claudia-opc-io`, a byte-splicing editor, the paragraph engine, loss codes) and odt is the first format on it (E9.5, D402). odp (E10.3, D412) and ods (E6.9, D413, formulas translated to OpenFormula, D414) followed: all three formats read, write and edit-and-reexport with maximum preservation, `meta.xml` is made and kept true from the log (D411), the text app can export tracked changes. The acceptance wants an import list and an export list for every format (the codes exist, D405; the screens do not) and every export opened in LibreOffice (odt: `scripts/odf_libreoffice_check.py` and a non-blocking CI job, D409).
