As an analyst, I want charts that update live and respond to clicks, so that I see my data.

**Acceptance:** bar and line first, then scatter; rendering per E0.3; the same look in web and desktop; a click-to-edit hook.

**Notes:** Charts are Plotly figures inside the page, the same in every shell. Plotly is the reason the whole web-surface architecture (D41, D42) was chosen. Bar charts landed end to end in the web client: a diagram definition (`ChartSpec`) is a shared object-layer "diagram" (D177), defined once and placed as a tab, a floating object, or both from the same id (D204); the server computes its Plotly figure on demand from live cells, pulled by the client after a touching `cells` event (D205); series use a validated fixed palette (D206); the first column is read as a header by range shape (D207), the first row only when an explicit toggle says so (D208, fixed after the owner reported rows being silently dropped). Still open: line and scatter kinds (`CHART_KINDS` is bar-only); a click-to-edit hook (clicking a bar back to its cells); the GTK/desktop client (web only so far — "the same look in web and desktop" is not yet true); interactive resize handles for a floating chart object (it drags like any object, but nothing in the UI calls the already-wired `resizeObject` yet); the palette is validated for light mode only, not dark; a symmetric header-column toggle (only the row got one, since that is the direction the reported bug showed up in).

**Status evidence:** `packages/claudia-computes/src/claudia_computes/charts.py` (`BAR_COLORS`, `figure_of`), `.../model.py` (`WorkbookModel.chart_figure`), `packages/claudia-server/src/claudia_server/computes.py` (the nine new RPC methods), `web/app/lib/charts.ts`, `web/app/components/ChartView.vue`, `SheetChartInsertDialog.vue`, and the `Workspace.vue`/`SheetGrid.vue`/`FooterBar.vue` wiring for Edit ▸ Chart…, the chart-tab strip and a floating chart object.
