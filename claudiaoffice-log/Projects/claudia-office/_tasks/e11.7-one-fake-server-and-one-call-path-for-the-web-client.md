As a developer of the web client, I want its tests to talk to one fake server that is checked against the real
server's protocol, and its sessions to call the server through one path. Then a renamed method, parameter or event
breaks a test instead of slipping through, and a new request is one line, not a hand-written wrapper.

**Acceptance:**
- One shared fake server for `web/tests`. It replaces the 19 hand-written `FakeLink` classes, which are 17 to 58 lines
  each. It answers what a document's opening needs for each app, takes per-test handlers, records the calls and pushes
  events.
- The fake server refuses a method, parameter or event that the server's own description (`MethodTable.describe`,
  served at `/api/<app>/protocol`) does not have. A test checks that the description it uses is current.
- The client's call policy lives in one place. That policy is: the revision a change is based on, the refusal for
  someone who may only look, the notice when a request fails, and waiting behind typed words in composes. Today it is
  split over `write()`, `attempt()` and plain `request()`, and the sessions repeat the
  `(await this.write(…)) !== false` shape about 80 times.
- Every web test that talks to a session uses the shared fake server. The web unit tests, lint and types stay green.

**Notes:** this is recommendation 3 of the architecture review of 2026-11-21. D1432 already made `write()` the one door
for changes, but each test file still fakes the server its own way, so the wire can drift from the real server without
any test failing. The `ObjectsEvent` shape was the example in the review. E3.2 (types generated from the same
description) is related: either can come first. If E3.2 comes first, the fake can use its types.
