As an owner, I want to add users (name, password, role) to my document, so that the history shows who really did what.

**Acceptance:** roles owner, editor and viewer; adding, removing and changing users; the name `ai` is protected; no central user database anywhere.

**Not done:** The owner should be able to make an editor a viewer only or make a viewer an editor;  key rotation; who may discard side history after a restore.

**Status evidence:** the directory now lives inside the document (`people.bin`, sealed with the content key) and `SealedDocuments` is both the provider and the user directory; `add_user` is owner-only and `ai` is refused. Two role changes are now built without remove-and-re-add: anyone can leave on their own (`leave_document`; needs none of the three domain keys, unlike `remove_user`) and an owner can hand ownership to an existing editor through a two-password propose/accept handshake (`transfer_owner`, time-limited, server-memory-only) — both reachable from File ▸ Manage (Leave document…, Assign new owner…, Accept ownership…) in all three apps, web and GTK.

**Decided 2026-11-19.** Roles change in place, owners only; removing or downgrading someone renews the keys she held (D1263); how the people who stay get the new keys is decided in D1274 (a sealed inbox, one public key per person; built in slice C). Only owners discard the side history a restore leaves (D1264). The container has room for a private domain per person (D1265).
