As an app developer, I want a Neutralino shell for Windows and macOS with the OS title bar and a native menu around the bundled frontend.

**Acceptance:** configuration with the native API restricted (allow lists, file scopes, one-time token); a native main menu from the manifest including the macOS application menu; native file dialogs; About, theme and scale from the OS; starts and stops the server bundle; installers; a thin adapter so Tauri or pywebview could replace Neutralino.

**Notes:** Depends on E0.3. Neutralino 6.8.0 has now run on one Mac and one Windows 11 machine with all automatic checks passing (D156). **Acceptance items learned from the spike, now built for macOS/creates and Windows/composes:** `tokenSecurity: one-time`, the page loads only `js/neutralino.js`, binary and client library pinned to 6.8.0, allow-list shrunk to exact methods only, six today on macOS (`file-dialog.ts` needs two more) and four on Windows, no `file-dialog.ts` there (D157); Edit items carry a Cocoa `action` and `shortcut` via the shared manifest's new `role` field on macOS, forward to the page unread on Windows, same manifest either way, the About dialog stays a page dialog on both (D158, printing still not wired on either); the transport question (D159) is answered and **confirmed on a real Mac, 2026-11-07** — `window.Neutralino` exists on the loopback page, built on the unmerged `macos-client` branch as `macos-client:clients/macos/src/launch.ts` + `page-bridge.ts`, **carried to Windows the same way, 2026-11-08, not yet confirmed on a real machine** — `clients/windows/src/launch.ts` + `page-bridge.ts`.

**Status evidence (macOS):** `macos-client:clients/macos/` (package `claudia-shell-macos`), branch `macos-client`, handed to the owner as a patch (no push access from this session). Identity, paths, a local server (`freePort`, SIGTERM/SIGKILL stop), the shared manifest turned into a native macOS menu (D44's app-menu relocation, D158's roles), the D159 page adapter, an esbuild bundling pipeline for the injected script, `neutralino.config.json`, creates' icon assets, a one-command `start-mac-client.sh` at the repo root (mirrors `start-client.sh`; fetches the Neutralino binary itself), and `file-dialog.ts` (swaps WKWebView's non-functional `<input type="file">` picker for `Neutralino.os.showOpenDialog()`) — all for **creates only**. 73 vitest tests, 10 pytest tests, `tsc --strict`/ruff/mypy clean; full notes in `notes/e5-11-macos-client.md`. **Not done:** composes and computes (no `apps/<app>/` folder yet, only `identity.ts` entries); installers, codesigning, notarization; printing as a contract message; translations. **Not verified:** the Cocoa-selector-plus-page-dispatch interaction on creates' actual slide editor; a Redo keyboard shortcut; what happens to the server if the window is killed outright; a second Mac, an older macOS, a screen reader.

**Status evidence (Windows):** `clients/windows/` (package `claudia-shell-windows`), branch `win-client`, handed to the owner as a patch (no push access from this session) — the pattern repeats for a second OS at the same depth (the owner's explicit "full E5.11 parity" choice). Identity, paths, a local server (`freePort`, one `kill()` call — no softer Windows signal exists, D161 leaves fixing an orphaned process on a hard kill open), the shared manifest turned into a Windows menu with **no application-menu relocation and no native `action` field** (D44, D158 — unlike macOS, nothing here reads `role`), the D159 page adapter, the same esbuild bundling pipeline, `neutralino.config.json`, composes' icon assets (the already-approved Linux glyph, rasterized), a one-command `start-win-client.cmd` at the repo root, and **no `file-dialog.ts`** (D216: WebView2 is Chromium and is expected to need no workaround, unlike WKWebView — not yet confirmed) — all for **composes only**, the inverse app choice from macOS's creates-first scope. The shared `manifest.py` also gained D158's `role` field as part of this patch (it was built for macOS but missing from this branch's own starting point) — the one change to code outside `clients/windows/`. 63 vitest tests, 10 pytest tests, `tsc --strict` clean; full notes in `notes/e5-11-windows-client.md`. **Not done:** computes and creates; installers, codesigning, a Start Menu shortcut; printing as a contract message; translations; a Windows Job Object for the orphaned-process gap (D161). **Not verified:** everything in this paragraph, end to end — four real runs (owner, same Windows VM, 2026-11-09) found and fixed a `build-inject.mjs` `ERR_UNSUPPORTED_ESM_URL_SCHEME` bug, then a `start-win-client.cmd` `uv sync` bug (installed the root `dev` group by default, whose `myst-parser` → `pyyaml` chain tried and failed to compile a C extension on a Python with no prebuilt wheel yet; fixed with `--no-dev`, which this client never needed anyway), then a `launch.ts` entry-guard bug (`import.meta.url` compared against a bare `file://${argv[1]}` template, malformed on Windows's backslashed drive-lettered paths, so `main()` was never called at all — fixed with `pathToFileURL(...).href`), then a `defaultSpawn()` `windowsHide` gap (`detached: true` alone pops up an empty console window for the server on Windows; fixed by adding `windowsHide: true` alongside it) — the fourth run got the server itself to actually start but stopped at its own 30-second startup timeout for a reason not yet understood (see `notes/e5-11-windows-client.md`'s "Fourth real run" — needs the server's own log, `%LOCALAPPDATA%\Claudia\composes\state\server.log`, to diagnose further rather than guessing). The first three bugs share the same shape (a Windows-path assumption POSIX never violates) and all three have an identical, unexercised twin already sitting in `macos-client:clients/macos/`.

Notes: `notes/e5-11-windows-client-complete.md`. **Not verified: any real Neutralino window on Windows** (and the old 30 s server timeout of the fourth real run, D161's orphan on a hard kill, HTTPS through the Windows store, `start-win-client.cmd` with arguments, WebView2 file input). **Not done:** self-signed certificates (D245); `pick_file`, links and printing from the frame; frame `sandbox`; status-screen design; installers, signing, Start Menu; a Job Object (D161).
