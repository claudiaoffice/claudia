As an operator, I want the server to hold a document's keys only while someone has it open.

**Acceptance:** keys live in memory only; sealed on last leave and on idle timeout; wrong-password attempts are rate limited; keys never appear in logs.

**Status evidence:** keys are pending after login, held while open and dropped by `release`; a byte scan of the folder after packing finds no names, passwords or chat text; the `sealed` close code (4423) tells a viewer to try again later. Hashing runs off the event loop behind a cap (SEC-03). **Not done: rate limiting.** The waiting caps bound how many sockets queue, but nothing slows a patient guesser who fails and reconnects (SEC-11).

**Built 2026-11-19 (D1275):** behind `--behind-proxy`, a connection is counted by the `X-Forwarded-For` entry the nearest trusted proxy appended (`--proxy-hops`, default 1), so the per-address caps of SEC-02 no longer hit everybody and the back-off to come has a real address to count. The back-off itself (D1266) and the hashing cost (D1267) are not built.

**Decided 2026-11-19.** Failed logins wait 1, 2, 4, 8 and 16 seconds after three free ones, per address (at most 30 s) and per document and name (at most 10 s), with no lock-out, for the document hello and the administrator's sign-in (D1266, SEC-11). The hashing cost rises with it (D1267). Which address counts behind a proxy is proposed in D1275, undecided.

**Done, 2026-11-22 (branch `e2-7-close`).** Every point of the acceptance is built and tested. Keys live in memory
only and are dropped by `release`, on the last leave and when an idle document is unloaded
(`test_an_idle_document_is_released_when_it_is_unloaded`). Wrong passwords wait longer each time (D1266, SEC-11):
`login_throttle.py` at the document's `hello` and at the administrator's sign-in, refused before any hashing, the state in
memory (D1276), the address behind a proxy as D1275 decided; the hashing cost is calibrated (D1267). Keys never appear in
logs: `test_server_keys_stay_out_of_logs.py` runs a whole session through the server at DEBUG and finds no key in any
form; two objects that would have printed keys in their text were fixed on the way (SEC-23).
