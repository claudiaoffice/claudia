As a user, I want missing fonts delivered automatically, so that a document looks right on any machine.

**Acceptance:** a library of OS fonts plus downloaded collections with licence metadata; WOFF2 served from our own server, never a CDN; the document's requirements checked on open; Microsoft fonts only where the licence allows, with metric-compatible substitutes.

**Status evidence:** the library `claudia-fonts` is built (62 tests): collections with a mandatory licence record, a catalogue by family with a digest and substitution table, refused and replaced fonts hidden from the engine, a WOFF2 cache for redistributable fonts only, `@font-face` CSS with escaped family names, and `fonts.conf` for the engine. **Not built:** the server routes under `/api/v1/fonts`, `providable_fonts` in the manifest check, `fonts.lock` and the fetch command, the starter set, and the web composable — so no document can actually be given a font yet.

**2026-11-12 (D905):** built: the routes `GET /api/fonts`, `/api/fonts/{sha256}` and `/api/fonts/{sha256}.woff2` (`claudia_server.fonts`, public, redistributable fonts only, immutable caching, a changed file refused), `--fonts DIR` on the server, the pinned starter set (`claudia_fonts/starter.lock.json`: Inter, Fraunces, JetBrains Mono, Carlito, Caladea) with `python -m claudia_fonts fetch DIR`, fetched by `./start.sh` and the Docker build, and variation axes in the catalogue. The routes are `/api/fonts`, not `/api/v1/fonts`. **Still not built:** `providable_fonts` in the manifest check, a per-document `fonts.lock`, `@font-face` for the editors (the print preview registers its fonts itself), and fonts for the desktop shells' local servers.
