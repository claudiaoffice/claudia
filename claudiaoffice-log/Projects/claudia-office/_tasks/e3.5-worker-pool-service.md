As a calculation developer, I want a shared pool of warm worker processes with timeouts and cancellation, so that slow code never blocks a document.

**Acceptance:** submit, cancel, timeout, crash containment; inputs by shared memory; bundle-compatible (E0.2); metrics.

**Notes:** The E0.2 spike proposes the lifetime protocol: lifeline pipe from shell to server, parent-sentinel watchdog in every worker, tree kill on timeout, kill-busy-first on shutdown. Tested on Linux only.

**Status evidence:** no `multiprocessing`, process pool or forkserver anywhere under `packages/*/src`. This is the root cause behind PERF-01, PERF-02 and PERF-05: everything runs on the one event loop.

**Status, from the code (2026-11-10):** moved from todo to in progress — the worker pool exists (`claudia_core` offloading, D134); the status evidence above predates it.

**Checked against the code, 2026-11-17 (`main` at `6814bac`).** What runs on the pool today: imports (`hub.workers.submit(import_state, …)` in `app.py`). Searches stop at a time budget instead (SEC-18). Calculation, packing and rendering still run where they did; `submit` has no memory cap (SEC-19).

**Added 2026-11-19 (salvaged from the branch `worker-pool`, D1316, D1315):** `WorkerPool.max_waiting` bounds the submissions in flight across all documents and `PoolBusy` refuses the next one at once; `Hub` takes `max_waiting`; `claudia_core.replay_collecting` makes the replay loop a pure function of a model and plain entries, ready to be sent to a worker (nothing sends it yet). Still not done: timeout, cancel, memory cap (SEC-19), metrics.
