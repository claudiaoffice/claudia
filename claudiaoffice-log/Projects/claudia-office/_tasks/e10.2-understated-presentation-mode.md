As a presenter, I want an elegant, laid-back presentation mode, with speaker notes and a time plan, so that I can tell my story calmly and know where I stand.

**Acceptance:** F5 and Shift+F5 start the show from the first or the current slide, filling the screen with the slide only; minimal transitions (none, or one quiet fade); a presenter view with the next slide, the slide's Markdown notes, the clock and the time against the plan; an overview to jump (`G`), blank (`B`) and end states; every slide may carry Markdown speaker notes and a planned time, both stored in the document, with the total of the times always in view; the show runs frozen on the revision it started from; presenting takes no locks and writes no command; the same on web and desktop, with an English and a German interface text for every label, a key for every menu entry, the notes passing through ODP and PPTX, and BITV in mind (slide titles announced, reduced motion respected).

**Notes:** Design, screens A–G and the open points are in `notes/e10-2-presenter-mode.md` and `notes/mockups/presenter-mode.svg`; decisions D291–D299 (D291–D295 confirmed by the owner, D296–D299 proposed). Screens A–G were agreed and the build started 2026-11-13. The second window and fullscreen depend on the spike in `spikes/e10-2-presenter-window/`, which has to be run in Firefox, the GTK shell and both Neutralino shells; until then the first version is the single-window show with `P` swapping to the presenter view. Notes and planned times are state schema 8 of `SlideModel`. Not in it: pointer, ink, builds, audience Q&A, remote viewers, recording, notes in print, automatic advance. Suggested split once the screens are agreed: notes in the model with ODP and PPTX; planned times; the show itself (audience view, presenter view, overview); the shell changes.

**Status evidence:** built on branch `presenter`: notes and planned times in the model, the server and the ODP and PPTX files; the single-window show (audience view, presenter view with Markdown notes and the clock against the plan, overview, blank, end, frozen deck); F5, Shift+F5 and Ctrl+Alt+P; German texts; menu entries in the three desktop shells' manifests. Unit tests in Python and Node and `web/e2e/present.cjs` green in Chromium. The spike was run by the owner in Safari on macOS (F5 combinations are system keys there: D295). **Open:** the second audience window and shell fullscreen (D296: Firefox, GTK, Neutralino not yet run), the presence line while presenting, `e2e/present.cjs` in Firefox, the owner's try-out of the show on a real second screen.
