As anybody reading claudia's code or using its UI, I want the words of `glossary.md` used for what they name, so that people and agents mean one thing by one word.

**Visible to people (UI strings and help):**
- "suggestion", "suggest" for the ai's offers → **proposal**, "propose"; the AI mode switch reads act / propose.
- "Suggest going back…", "The suggestion to go to {label} was declined/withdrawn" → "Propose going back…", "The proposal to go to {label} …".
- "Add a tag…", "A document has at most {count} tags" and the like, for the words on a document → **keyword**.
- "tags in the chat" (E5.20) → **references** in the chat.

**In the code (names only, no change of behaviour; claudia is pre-release, so stored names are renamed outright, without upcasters or shims for existing documents):**
- `assistant` (the assistant's account, `assistant.py`) → **ai**.
- `Entry` (`log.py`) → **step**.
- `Line` (`Document`, `restore-N`) → **branch**, as `log.py` and `Revision` already say.
- object kind `rendered` → **container**; object kind `diagram` and `DiagramDefinition` → **chart**.
- `block` for a composes paragraph (`block_kind`, `block_names`) → **paragraph**.
- composes `Suggestion`, `ProposeSuggestion`, `ResolveSuggestion`, `AcceptSuggestion`, ai mode value `suggest` → **proposal**, `propose`.
- the `claudia-container` package is the document file, not a container: rename when convenient.

**Acceptance:** none of the left-hand words names these things in UI strings, help or code identifiers any more; test fixtures, test documents, specs, importers and exporters use the new names; tests and E2E pass.
