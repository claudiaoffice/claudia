As a writer, I want pages that break the same way everywhere, so that printing is predictable.

**Acceptance:** a decision on the layout approach (server-side layout, or reflow without pages) using the E0.5 measurements.

**Notes:** With the full LaTeX engine (D88) server-side layout is real: the page view could show pages typeset by the engine, so page view and PDF match; the cost is latency while typing and a second layout engine beside the flow view. Engines differ per shell, so identical line breaks cannot be assumed. The page view built today is approximate and is not this story.

**Status evidence (2026-11-12):** decided by D901: pages are laid out in the client by one deterministic TypeScript library, `@claudia/layout` (`layout/`, D902), shaping with pinned HarfBuzz WebAssembly (D903), by the rules of D909, the same byte for byte everywhere (D910). The layout spike measured it on Linux, Windows and macOS in Chrome, Firefox and Safari. The print preview (D906) is the first user of it; the page view is not yet (E9.24).
