As anybody reading claudia's code or using its UI, I want the security words of `glossary.md` (section Security) used for what they name, so that people and agents mean one thing by one word. Companion of E1.18, kept apart because E1.18 is in progress on another branch.

**Visible to people (UI strings and help):**
- "login", "log in" for giving one's name and password to a document → **unlock**. The owner worried that "unlock" is new to many people: agree the wording of the unlock screen with a mock first.
- "recorded in the document's history" for exports, prints and PDFs → the **exit record** (UX-63).

**In the code (names only, no change of behaviour; pre-release, no compatibility for existing documents):**
- `Domain` (content, history, chat, private) → **part**; "private domain" → **private notes** (or the part that holds them).
- `Manifest` and "details" (`clean_details`) for what can be read without unlocking → **cover**.
- the audit record (`audit.py`, `AuditRecord`, `AUDIT_KINDS`, `AUDIT_PARTS`) → **exit record**.
- `Unlocked`, `unlock_with_recovery` already say **unlock**; the server's login routes and messages follow.

**Acceptance:** none of the left-hand words names these things in UI strings, help or code identifiers any more; tests and E2E pass; the German catalogs are compiled with the strings (`scripts/compile_mo.py`, `scripts/po_to_json.py`).
