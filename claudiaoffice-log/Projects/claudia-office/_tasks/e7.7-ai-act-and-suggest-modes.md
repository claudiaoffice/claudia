As a person working with the AI, I want to choose whether it acts at once or only suggests when I ask something of it, so that I decide how much it does without my review, and a colleague can choose differently in the same document.

**Acceptance:** a switch in the panel of all three apps, "act" or "suggest", per person and per document, kept on the client and sent with each `@ai` request (the server stores nothing). In *act* the AI works in a loop (reads, changes, checks the effect, corrects). One AI answer is one undo unit, and the asker has an "undo the AI's last answer" action although the AI itself may not call `undo`. The history says "ai, on behalf of X". Tested with two people in one document, one in each mode, asking at the same time. The switch is in all three apps from the start, creates included (E7.9). **The default is suggest in all three apps** (decided 2026-11-11), so a person who never touches the switch gets proposals, not changes.

**Notes:** supersedes D63's "suggestions only" (D262). The default is suggest everywhere (D262). Depends on E7.4 (the per-request account carries the mode) and, for *suggest* in computes and creates, on E7.8, which therefore comes before the AI writes anything there. Composes' anchored suggestions are its suggest mode as built. In act there is no review step against instructions planted in the document; the allow-list, the asker's role and the one-step undo bound it. Design: `notes/e7-ai-agent-design.md`, mock-up `ai-suggest-mode.svg`.

**Built 2026-11-11 (branch `ai_server`):**
- *Server half* (claudia-server 0.22.0): `chat` takes `ai_mode` (`act`|`suggest`, not stored); no mode meant *suggest* (later the same day; reversed by QA on 2026-11-12, UX-20: a request without a mode now gets *act*, `ai_mode.UNSAID_MODE`, while every client sends its mode); each question runs under its own account (`Assistant.account_for`); in *suggest* the AI writes nothing in computes and says so, composes keeps its `suggest`; the model is offered only the tools the asker's mode allows.
- *Loop* (claudia-server 0.23.0): read tools and a bounded loop, see E7.5.
- *The switch* (web): "When I ask the AI, in this document: Act at once | Suggest first" at the top of the chat in the side panel (`SidePanel.vue`, radio group), per person and per document (the key is server and document, `lib/ai-mode.ts`), kept in the browser's local storage, *suggest* when nothing is stored or the storage is unreadable, sent as `ai_mode` with **every** chat message (`BaseSession.say`). It is in the panel of all three web apps, and therefore in the GTK client, which shows the web app in a web view. In composes both choices behave as *suggest* for now (no direct edit method yet) and the panel says so; creates has no model yet (E7.9), the switch is there ahead of it.

**Not built:** one answer = one undo unit with an "undo the AI's last answer" action, and the `on behalf of` attribution (it changes the log entry, a document-format decision; next), and the two-people-at-once test in a real document (the server half is tested with two askers in `test_server_ai_account.py`; the browser half is per person by construction).

**QA 2026-11-12 (UX-20):** the server read a missing mode as *suggest*, against the build note above and `chat`'s own description, so with no client sending a mode the AI in computes changed nothing. Now a missing mode is *act* (`ai_mode.UNSAID_MODE`); `DEFAULT_MODE` (*suggest*) is what a client starts with once it has the switch. Still to build: the switch in the three clients (`notes/mockups/ai-suggest-mode.svg`), the loop, and undo of the AI's last answer.
