As a person who gets slide decks, letters and sheets from colleagues using PowerPoint, Word or LibreOffice, I want Claudia to show me which fonts in a file are missing, what stands in for each of them, and to write the original fonts back on export, so that a document never changes its look without my knowing, and I can get the real font right away when it exists.

**Why (owner, 2026-11-16):** moving from PowerPoint to LibreOffice Impress, decks from colleagues changed their look completely and could not be worked on, because fonts were swapped silently, also by metric-compatible ones such as Liberation Sans for Arial. Same widths keep the line breaks, but not the look. Also: being able to show an imported document with exactly the fonts it was written with matters a lot.

**Owner's requests so far:**
- An imported Arial stays Arial in the document and is exported as Arial; the stand-in is temporary.
- The stand-in is made clear at three moments: **on import** (list each font and its stand-in), **while working** ("Arial, represented by font X"), **on export** (X will be replaced by Arial).
- A simple way to get missing fonts right away: a downloader that knows typical sources (Google Fonts, Microsoft's downloadable fonts, LibreOffice's Liberation fonts), in both directions.
- Font management primarily in the server settings; users must also be able to add missing fonts from the desktop clients.
- Asked whether keeping fonts inside every document makes it too large (answer: keep only fonts that don't ship with Claudia), and why the server keeps fonts at all (answer: it is the shelf to choose from, holds fonts that may not travel, and feeds LaTeX).

**Design (proposal, mock-ups to agree before code):** `notes/e3-3-font-management-ui.md` and `notes/mockups/fonts-1…7-*.svg`:
1. Server settings ▸ Fonts: collections, families, stand-ins, problems; Add fonts… with a check step (boards 1–2).
2. Format ▸ Fonts… (Ctrl+Alt+E) in all three apps: each font the styles ask for, with status As written · Kept · Other version · Stand-in · Missing; Add font…, Replace…, keep fonts inside the document (board 3).
3. The style's font field from the catalogue; Add a font to this document (desktop: installed fonts; web: a file) (board 4).
4. Import: a Fonts step in the import dialog (board 5). While working: a "≈ N stand-in fonts" chip, View ▸ Show Stand-in Fonts (Ctrl+Shift+Alt+B), "Arial  shown as Liberation Sans" in the font field (board 6). Export: a Fonts section writing each original name back, or the stand-in embedded on request (board 7).

**Slices and acceptance:**
- **a · Metric-compatible fonts shipped.** Arimo, Tinos, Cousine (Arial/Helvetica, Times New Roman, Courier New), Gelasio (Georgia), Selawik (Segoe UI) join the pinned starter set with licence records; the substitution table points at them; Arial no longer falls back to Inter. Tests on `Catalogue.resolve`.
- **b · Stand-ins as data.** The resolver reports, per requested family: provided family, how close (same font / same widths / other widths), source. The manifest check uses it; `FontRequirement` gains the file's SHA-256 (and D911 axis values).
- **c · The three moments.** Import step, header-bar chip and View toggle, font field "shown as", export section — in composes, computes and creates, desktop menus included, every entry with a shortcut, strings in the `.po` catalog, status in words (BITV). The requested name is never rewritten: a round trip .pptx → Claudia → .pptx keeps Arial.
- **d · Getting the real font.** A shipped index of font sources: open fonts (Google Fonts at a pinned commit, Liberation, Selawik) fetched by the server on request, checked by SHA-256, never by the browser; Microsoft's downloadable fonts (core fonts, Aptos) only on the desktop clients, with the licence shown; fonts installed on the computer offered by the desktop clients. Import counts which slides or columns break differently.
- **e · Fonts inside the document.** Fonts that don't ship with Claudia are kept in the sealed document by hash; importers take embedded fonts from .docx/.pptx/.odt/.odp; exporters embed open and carried fonts where the font's embedding bits allow.
- **f · Server settings ▸ Fonts.** The admin page and Add fonts…, with the three-way "may go" licence answer if agreed.

**Open questions (owner):** three-way "may go" (Anywhere / This server / Not usable) instead of D94's yes/no; keep non-shipped fonts in documents by default; users add fonts to the document, administrators to the server; `fsType` as the rule for adding a font to a document (would allow Calibri from one's own Windows computer); shortcuts Ctrl+Alt+E and Ctrl+Shift+Alt+B; whether View ▸ Show Stand-in Fonts is worth it.

**Before code:** agree the boards; then an architecture/class diagram of where the pieces go (resolver result type in `claudia-fonts`, font requirements in `claudia-core`'s manifest, the sources index and fetch in `claudia-fonts`, the routes in `claudia_server.fonts`, the importers' and exporters' font handling per app, the shared Vue components for the three moments), then slice a, test first.
