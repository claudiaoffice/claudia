As an author, I want to write a LaTeX formula or a Mermaid diagram as text and see it rendered in all three apps.

**Acceptance:** an insert action per app takes LaTeX or Mermaid source, shows a live preview and renders in the document, with the source editable and the truth; a text block can be set to LaTeX text for typeset paragraphs; the rendered SVG is stored as a content-addressed cache so exports need no browser, rebuilt when the renderer version changes; LaTeX goes through the full engine, Mermaid runs in the frontend at strict security level, and rendered output is always an image, sanitised on export; errors shown next to the source with the line, never blocking saving; bundled offline, sizes measured, fonts via the font service.

**Notes:** Mermaid's licence and bundle size are to check (E11.2). Mermaid now runs on the server through `mmdc` and a Chrome the administrator installs (D392), not in the frontend; the acceptance line about the frontend is superseded by that.

**Built (branch containers, D390-D396):** the `rendered` object kind in all three apps' models; the `claudia-render` plugin layer (manifests, tool registry, service, LaTeX / Mermaid / Typst); wire methods and background rendering in the hub with a `render_result` event; ODP and PPTX export of the picture; help topic. See `implementation-notes/rendered-text-containers.md`.

**Open:** screen designs (SVG mockups) and then the insert action, live preview, double-click source editing and error display in the web, Gtk and Neutralino clients; composes object add on the wire; async submit/status job API (D92); source embedded in Office files and native formulas; `rsvg-convert` through the sandbox; live change of the tool settings; text block set to LaTeX text.
