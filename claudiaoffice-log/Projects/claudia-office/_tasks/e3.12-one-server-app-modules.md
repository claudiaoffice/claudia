As somebody who uses Claudia, I want one server for all three apps, so that one list can show all my documents and my computer runs one server, not three.

**Acceptance:** one process serves computes, composes and creates (`--apps`, all by default) from one origin and port; documents of each app in their own place (`DIR/<app>/`) and addressed as `/api/<app>/docs/<id>/ws`, the old address still working; `/api/docs` lists the documents of every app; limits, access secret, administrators and settings per server; old commands (`--model`, `CLAUDIA_APP`, `./start.sh <app>`) keep working; `--exit-when-idle` with the presence socket; a folder lock; the web client and the three desktop shells use the one server (their own patches); heavy jobs offloaded to the worker pool; later, module workers (D436).

**Notes:** Patches, in this order: server (this story's first), web client (after its screens are agreed), Linux shell, macOS shell, Windows shell, offloading. Lazy import of modules (so a one-module server loads one app) belongs to the module-worker step, where it pays off. The AI server question (one runner for all apps, queueing) is left to E7.1.

**Status evidence (server patch, 2026-11-14):** `packages/claudia-server/src/claudia_server/suite.py` (`Suite`, `Module`), `folder_lock.py`, `idle.py`, the routes in `app.py`, `--apps` and `--exit-when-idle` in `cli.py`, `scripts/start.py`, `docker/entrypoint.sh`.

**Status evidence (import and web patches, 2026-11-14):** `packages/claudia-server/src/claudia_server/uploads.py`, `packages/claudia-server/src/claudia_server/formats.py`, `web/app/components/OpenDialog.vue` (My places, Collections, Mine, search, Open a File…, File ▸ Open in a dialog), `web/app/components/ImportDialog.vue`, `web/app/lib/mine.ts`. Still open: the three desktop shells (one shared local server, Mine in `shell.json`), moving the browser scripts from three one-app servers to the one server, and the offloading of D436 beyond the import.
