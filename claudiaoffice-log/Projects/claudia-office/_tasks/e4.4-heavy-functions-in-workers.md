As a function author, I want slow functions to run in worker processes, so that they do not block other users.

**Acceptance:** functions declared heavy, or measured slow, run in workers; calls batched per dependency layer; timeout, cancel and crash containment demonstrated.

**Notes:** Needs E3.5.

**Status evidence (2026-11-19, salvaged from the unmerged branch `worker-pool` onto `e1-core`, D1314–D1316):** a `UserFunction` can declare `heavy` and `heavy_above` (`claudia_computes/functions/base.py`); a call past the threshold raises `Deferred`, its arguments are frozen into a `FrozenGrid` (`functions/range.py`) and filed in `Calculator.pending_heavy` (`claudia_computes/calc.py`); a worker's answer lands as the logged, non-undoable `ApplyCalculated` command (`claudia_computes/commands.py`); `HeavyDispatcher` (`claudia_server/heavy_dispatch.py`, one per workbook document, attached in `hub.py`) runs it on the pool and discards an answer that arrives after the inputs moved. Tests: `test_heavy_functions.py`, `test_frozen_grid.py`, `test_apply_calculated.py`, `test_heavy_dispatch.py`, `test_server_heavy_dispatch.py`. **No function of the library is heavy yet**, so nothing dispatches in a running server today: the machinery waits for its first user. **Not done:** a heavy call inside a larger expression (only a call that is the whole formula resolves), calls batched per dependency layer, timeout, cancel and crash containment (E3.5), the "calculating" cell state (E4.3, needs a mock first), and a measured, not declared, "slow".
