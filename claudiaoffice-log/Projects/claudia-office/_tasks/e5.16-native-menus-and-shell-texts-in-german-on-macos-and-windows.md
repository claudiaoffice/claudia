As a German-speaking person on macOS or Windows, I want the native menu bar and the shell's own messages in the App Language I chose, so that nothing around the page is English when the page is German.

**Acceptance:** the generated menus of `clients/macos` and `clients/windows` are read through the catalog (`po/de.po`) for the language the page reports, falling back to English; the shell's own messages (start-up and connection problems, the Open dialog's overlay) are catalog entries too; a language switch in Config ▸ App Language reaches the native menu on the next launch at the latest, as on Linux (D160); a test per client proves that no label of the generated menu is missing from the German catalog.

**Notes:** The page itself is complete in German (D320) and switches live in every shell. Only the chrome around it is not: `clients/*/src/generated/menu.<app>.json` carries the English labels of `manifest.py` and `clients/*/src/shell-page-entry.ts` passes `navigator.language` on without using it. The two clients duplicate their code on purpose (D116), so the change is made twice. Nothing about this needs a decision beyond D160's: one `.po`, no second catalog format.

**Status evidence:** Not started. Found while completing the Linux shell's strings (branch `i18n`, patch 2): the Linux client translates its native menu from the shipped `.mo`; the Neutralino clients have no translation step at all.
