As an owner, I want several passwords to open one document, so that roles can have their own.

**Acceptance:** each password derives (Argon2id) a key that unwraps the domain keys of its role; changing a password rewraps the keys without re-encrypting content; an optional recovery key, with it documented that a lost password without one means a lost document; known-answer tests and a review of the scheme.

**Status evidence:** built in `crypto.py` and `slots.py` — Argon2id with bounded parameters, HKDF with distinct labels, a locator derived from name *and* password so names never appear in the file, password change, and a recovery key (13 groups of 4 base32 characters, shown once). Known-answer tests from RFC 5869, RFC 9106 and the GCM vectors. **Not done:** an external or structured review of the scheme (part of E2.8); key rotation; and the KDF cost is uncalibrated — the default measures about 0.09–0.4 s against the 0.5 s target of D109.

**Decided 2026-11-19.** Hashing targets 0.75 seconds, calibrated on the server's own hardware, with a floor, a memory ceiling and a server setting; it applies to new documents (D1267). Key rotation is built with removal and downgrade (D1263). A slot may carry the key of a person's private domain (D1265). The review of the scheme is E2.8 (D1273).
