As an app author, I want skills and persona files per app, so that the AI behaves right in each.

**Acceptance** (agreed with the owner on 2026-11-23, after a real-key test of E7.11 showed that a long request in a text and any request that makes a slide object went wrong):

1. Each app ships `ai/persona.md` and `ai/skills.md` in its own package (computes, composes, creates); English only, not in the translation catalogues; no administrator override yet. A loader finds them by the package of the document's model class, so an app gets only its own files (a test shows it).
2. The persona (tone, brevity, the asker's language, never invent, ask when a request is ambiguous, look before changing, **look in the help first for how-to questions**) and the recipes are given to every provider, always. Together at most 6,000 characters per app (a test).
3. A recipe names the requests it uses and has a worked example; it is given only when every request it names is offered to this asker (a viewer and suggest mode get no write recipes; composes has a twin "Propose a rewrite" for suggest mode).
4. First recipes: computes: write values and formulas, add a sheet, find and replace. composes: write text into an empty document, rewrite a passage, propose a rewrite, apply a style, build a table. creates: add a slide, write words in a text box, draw a shape, speaker notes, move and resize.
5. `help_search` and `help_topic` are look requests in all three lenses, so the model is told about them; their answers are shown as plain text.
6. Fixed first, on the same branch: CODE-81 (the model was shown doubled braces where a request is explained) and CODE-82 (an empty final answer says "I could not comply." or "I made these changes: …"; Claude has its own answer length, `claude.max_tokens`, 4096 by default, on the AI page; the local model's stays 512).
