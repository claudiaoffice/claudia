As a user, I want my document as one compressed file, so that it is small and easy to move.

**Acceptance:** a ZIP container with manifest, command blocks, content-addressed assets and an optional snapshot cache, with a format specification; atomic writes, so a crash during editing loses at most the journal tail; a write-ahead journal folded into the container when the document is idle or closed; a small plain part of the manifest readable without any password, so the server can list sealed documents.

**Status evidence:** nearly all of it is built in `claudia-container`: the zip with `format`, `manifest.json`, `slots.json`, `people.bin`, `head.bin`, `content/snapshot.bin` and `history|chat/NNNNNN.blk`; blocks framed, zlib-compressed and AES-256-GCM sealed with additional data naming document, domain, number and the previous block's hash; a head record detecting removed or extra blocks; atomic replace; a journal with CRC and torn-tail repair; reader limits against zip bombs, `..` paths, duplicate names and lying sizes. **Not done:** the format specification in `docs/`; packing still rewrites the whole zip (PERF-06); an older copy of the whole file can still be put back.

**Decided 2026-11-19.** An older copy of the whole file put back stays undetected and the specification and the help say so (D1268). Packing may keep rewriting the whole zip up to about 50 MB (D1269). The format specification in `docs/` is written in this round and carries the audit chain (D1271) and the private domain (D1265).

**Done, 2026-11-22 (checked against `main` at `64166e2`).** The format specification is `docs/document-file-format.md` (renamed with the package, D1430); it carries D1265, D1268, D1269 and D1271. Rewriting the whole zip is accepted up to about 50 MB (D1269); what is left of PERF-06 is that threshold packing blocks the event loop, a performance bug and not part of this story. Accepted by the owner: D1268's "the help says so" is met by `docs/server.md` (no in-app help topic on document security yet); pictures are content-addressed in the document (sha256 id, kept once, D1431) but travel base64 inside the history block that added them and again in the snapshot, with no `assets/` entry of their own; that can be added later without breaking the format.
