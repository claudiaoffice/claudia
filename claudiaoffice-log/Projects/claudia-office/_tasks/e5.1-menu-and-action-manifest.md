As a developer, I want one manifest for menus, shortcuts and labels, so that GTK and web menus cannot drift.

**Acceptance:** File, Edit, Tools and Help generated into GMenu XML, a Neutralino main menu and a web menu from one source; labels are translation keys; every action carries a help topic id and a tooltip; Undo and Redo enabled from the person's own undo stack.

**Status evidence:** a manifest exists but only inside the Linux client (`clients/linux/src/claudia_shell_gtk/manifest.py` plus `data/webroutes.json`), and it **maps between two different menu structures** rather than generating one: the web app has six menus (File, Edit, Format, View, Tools, Help) against D4's four, and the shell carries them out by clicking the web app's own menus through `shim.js` (D117, UX-09). No translation keys, no help topic ids. **Blocked on the open decision UX-06**: four menus or six. *Added 2026-11-07:* the Neutralino run shows an Edit item needs a **role** (undo, redo, cut, copy, paste, select all) beside its accelerator, which on macOS becomes the Cocoa action and shortcut (D158); `manifest.py` has accelerators in GTK syntax but no role field.

**Checked against the code, 2026-11-17 (`main` at `6814bac`).** Most of the status above is history: the menus are the seven of D120 in every app and shell, `shim.js` is gone (D121), and the one manifest (`clients/linux/src/claudia_shell_gtk/manifest.py`) generates the GTK menus, the Neutralino menus (`clients/neutralino/src/generated/menu.<app>.json`) and the web app's key table (`scripts/generate_keys.py` → `web/app/lib/keys.generated.ts`); every action has a tooltip, its accelerators, the Edit `role` (D158) and who listens for the key; the shell gets enabled states from the page (`action_state`). **Still not done:** the web app's menus are a second copy of the structure (`web/app/lib/document-menus.ts`, CODE-32), no help topic id per action, and the Neutralino menus are not translated (E5.16).
