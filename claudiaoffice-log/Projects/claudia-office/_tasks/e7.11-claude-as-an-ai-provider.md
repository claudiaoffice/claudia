As an administrator, I want to add Claude in the server settings, so that `@ai` in our documents is answered by Claude the way a local model would answer it.

**Acceptance:**
- *Server settings ▸ AI.* A switch between the three AI providers (scripted stand-in, local model, Claude). For Claude: the provider key (write-only, only its last four characters shown afterwards, Replace and Remove; `ANTHROPIC_API_KEY` or a key file given at start wins over the saved one), the model name (free text with suggestions, a Sonnet-class default), the longest answer and the timeout. Applying asks Claude one test question first and refuses the change with the reason when that fails. The administrator's confirmation that document content is sent to Anthropic is recorded with who and when; without it Claude cannot be applied.
- *The Config menu is renamed Preferences in all three apps, the web app and both desktop clients (menu matrix, To decide #3), with its translations; where the menu sits on macOS stays an open point of the matrix (#14, #15).*
- *Owners' consent, in the Preferences menu ▸ AI… in all three apps, next to App language and Shortcuts, not in File ▸ Manage, which is for files.* Off by default; only owners change it; everybody else sees it read-only. It names Claude (Anthropic), says what leaves the server (the question, the earlier chat between the asker and the ai, and the parts of the document the ai looks at for her) and records who allowed it and when. It is consent for that one provider: when the server uses another remote provider, the owners are asked again; removing and re-adding Claude keeps it. Switching it off stops a running question before its next round to Anthropic, and the chat says "Stopped: Claude was switched off."
- *Who answers.* With the server's approval and the owners' consent, Claude answers and the ai's row in the panel carries the badge "Claude · remote"; every answer from it is marked remote. Without both, `@ai` in that document is answered by the local model, or by the stand-in when there is none, and says so.
- *Failure.* When Claude cannot answer (key refused, credit used up, rate limit, API overloaded, no network) the ai says in the chat "<AI type> is not available at the moment. The administrator can see why." There is no silent fallback to another provider for that question. The settings page shows the last error with its time.
- *First slice.* Claude sits behind today's `LanguageModel` interface and the same prompt and `commands` convention as the local model; one question is answered at a time.
- *Checked* against a local fake of Anthropic's Messages API, errors included; the owner makes one check with a real key before accepting.

**Out of this story:** a daily spending cap; Ollama; streaming; native tool use and a concurrency of Claude's own (E7.3); Claude connecting in (a person's own Claude app, parked in D266); Amazon Bedrock, Google Vertex and Microsoft Foundry as ways to reach Claude (follow-ups).
