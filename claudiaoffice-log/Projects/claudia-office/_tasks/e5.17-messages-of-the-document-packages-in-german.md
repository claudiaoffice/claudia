As a German-speaking person, I want the reason a request was refused to be in German even when it comes from the document itself (a cell reference that does not exist, a style name that is taken), so that no error is half English.

**Acceptance:** an error raised in `claudia-core`, `claudia-computes`, `claudia-composes` or `claudia-creates` that reaches a person carries a stable `code` and its parameters, and the server says it in the connection's language through the `detail` the protocol already sends (D322) without the packages loading a catalog; the `ValueError`s of the user and administrator directories that the admin pages show are said in the language the admin page was opened in; the stand-in assistant's chat texts follow the language of the person who asked; a test per package proves that no message of a user-reachable error is missing from the German catalog.

**Notes:** D322 did the server's own messages (about 126 templates). What is left is about 400 raise sites in the packages, `str(exc)` as the message of a `command_error`. Work through the ones a person can reach first (cell and range errors in computes, style errors in composes and creates, import and export errors); an error only a bug can raise stays English. The admin pages have no document connection, so they need their own language (the browser's `Accept-Language` or a setting).

**Status evidence:** Not started. Found while converting the server's `RequestError` sites (branch `i18n`, patch 3).
