As the owner who approves scenarios before they are built, I want every scenario in `claudiaoffice-log/specs` to be
run by a test, or to say which test checks it, so that an approved behaviour cannot quietly go unchecked. And as an
agent who runs "use it before delivery", I want `./run-e2e.sh` to run the same browser scripts CI runs, so that a
change that passes on my computer does not fail in CI for a script I never ran.

**Acceptance:**
- A test fails when a `.feature` file is neither bound to a test, nor tagged with the test that checks each of its
  scenarios, nor marked as a draft waiting for the owner's review (`@draft` on its `Feature:` line).
- The files that cannot be bound yet stand in one list in that test, each with the story or bug that binds it. The
  test fails when an entry is no longer needed, so the list only shrinks.
- One list of the browser scripts, read by both `./run-e2e.sh` and CI; `objects.cjs` and the two desktop-shell scripts
  run on a computer too.
- Without a browser, the specs are skipped with a reason instead of failing.
- `./run-e2e.sh --list` and `running.md` give counts that cannot go stale.
