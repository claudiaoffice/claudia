As a user of any app in any client, I want the same Search & replace panel, found at Edit ▸ Search & replace…, so that I search a table, a text and a presentation the same way.

**Acceptance:** one frontend component used by all three apps in every shell, talking to a `SearchHost`; `edit.search-replace` is one item of the shared Edit block in `web/app/lib/document-menus.ts`, between the clipboard group and the app's own items, with Ctrl+F and Ctrl+H in the shared shortcut table; the GTK and Neutralino menus come from the same manifest with an accelerator and role (`clients/linux/src/claudia_shell_gtk/manifest.py`, the macOS and Windows manifests); the panel is non-modal, keyboard-operable from the first Tab, announces "N matches" to screen readers, marks matches by more than colour, works in dark mode and in Firefox; builder, matches list, "Left out", Replace with kept-part chips and the ⋯ menu with "Write the pattern yourself…" are as in the agreed screens; every label is a translation key and no sentence is glued from pieces; Help has "About searching and patterns" with worked examples; component tests, then an e2e test per app.

**Notes:** Needs the screens agreed first (project rule). Nothing of a search is saved in a document, so there is no import or export to OpenDocument or Microsoft formats; the formats' own find functions are not involved. The desktop clients need the menu entry and accelerators only, since they frame the web app.

**Status evidence:** Designs only so far: `notes/mockups/search-replace-edit-menu.svg`, `computes-search-find.svg`, `computes-search-builder.svg`, `computes-search-replace.svg`, `search-pattern-as-text.svg` and `search-in-composes-and-creates.svg`, described in `notes/search-and-replace.md`. Waiting for the owner to agree the screens; no code yet.
