As a translator, I want every text to come from translation catalogs, so that Claudia can be translated.

**Acceptance:** gettext `.po` as the single source, read by both GTK and web; extraction in CI; English complete; a test language proves nothing is hard-coded; numbers and dates typed by a user are parsed with that user's locale before a command is made.

**Notes:** D31 says i18n is built in **from the start**; it is the oldest unstarted decision in the log, and the cost of retrofitting grows with every screen.

**Status evidence:** groundwork built (D148) — kernel error codes, the protocol's `locale` field, a GTK gettext
skeleton and a web loader skeleton, `po/claudia.pot` extraction gated in CI, a pseudo-locale proving the
pipeline. **Now also (D160):** a working `Config ▸ App Language` switch in both shells (`manifest.LANGUAGES`/
`web/app/lib/i18n.ts`'s `LANGUAGES`, English/Deutsch), with every manifest menu/action label and tooltip plus
`SidePanel.vue`'s History/Chat headers (146 msgids) flowing through `_()`/`t()`, and a real `po/de.po` behind
them — the web page's own UI switches live, the GTK shell's native chrome re-translates on next launch. Still
open: most interface text elsewhere has not moved off plain English into `_()`/`t()` yet; numbers/dates typed
by a user are not locale-parsed before a command is made; only English and German exist.

**Now also (D320, D321):** the whole web interface goes through `t()` (936 msgids, all translated into German),
with one shared language for the page, `TransText` for sentences with markup, whole sentences instead of composed
nouns, `scripts/update_po.py` (and its gate check) to keep each `.po` in step with the template, and English
menu labels in Title Case. **And** the Linux shell's remaining messages (start-up and page problems, the download
toast, the About links, `--help`, the install hint), with the language now installed before the command line is
read. **And** the server's own messages (D322: `msg()`, said in the connection's language), the help topics and the function
descriptions (D323, E13.8). Still open: the native menus of the macOS and Windows shells (E5.16); the document packages' error messages,
the admin pages and the assistant's chat texts (E5.17); locale-aware parsing of typed numbers and dates.

**Status, from the code (2026-11-10):** moved from todo to in progress — the gettext pipeline, a pseudo-locale and a real German catalog with Config ▸ App Language are built (D148, D160); most interface strings are not in the catalog yet.
