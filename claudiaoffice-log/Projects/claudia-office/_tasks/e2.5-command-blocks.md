As an operator, I want commands grouped into compressed, encrypted blocks, so that the file stays small and redaction is cheap.

**Acceptance:** a block size policy; appending without rewriting old blocks (relaxed to a size trigger, D1269); the compression ratio measured against per-command encryption on real logs.

**Status evidence:** blocks are built (about 1 MiB each, framed, zlib-compressed, sealed, chained by hash). **Not done:** the size policy as a stated decision, the measurement against per-command encryption, and appending without rewriting — packing writes the whole zip again.

**Decided 2026-11-19.** The block policy is written down: 1 MiB before compression, closed blocks are not changed except by redaction, key renewal and deleting a private domain, the last open block is replaced as it grows (D1269). The measurement against per-command sealing is part of this round. "Appending without rewriting old blocks" in the acceptance is relaxed to a size trigger of about 50 MB (PERF-06).
