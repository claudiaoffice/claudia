## The owner's questions

**Do all desktop clients talk to the newest server?** Yes, as far as anything without a Mac or a Windows machine can
show. The three shells start the same command line (`--no-tls --dir --state-dir --web --exit-when-idle`, every flag
exists in `claudia_server.cli`), recognise a server by `/api/health` (`ok`, `apps`, and `version` from this computer
only, which the server sends), compare it with `python -m claudia_server --version` (0.36.0 on both sides), keep
`/api/presence` open, use 8765 or `CLAUDIA_SERVER_PORT`, write the port file whole, and say `welcome.app` with the
`files` capability. The page they show is the server's own web app, so its protocol (version 2) always matches. The
replay's list of reads (`VIEW_READS`) is the same on both sides. **But** the Windows and macOS menus were stale (no
Insert ▸ Container): fixed, and the gate now checks it. Known and still open: a server started from another checkout of
the same version is taken for this computer's own (the version check cannot tell checkouts apart); `./start.sh` cannot
bind 8765 while a desktop server runs there.

**Does every object users can add have a name?** Now: objects of every kind in all three apps (text box, shape,
picture, chart, container), slides, sheets, chart tabs, named ranges, tables and query results (`test_things_have_names.py`
adds each over the wire and reads the names back). Two gaps were found and closed: a new presentation's first slide had
no name (UX-40), and a text's paragraphs were not things at all (UX-41, D554: headings, list items and paragraphs, named
when first pointed at). Still without names: styles (they have names of their own, outside the namespace), a list as a
whole (reached through its items), and what an import brings in (named when somebody first points at it; names in the
Office and OpenDocument files are neither read nor written, and an object's name is lost on pptx/odp export without a
word: CODE-25).

**Is the file handling with the uid, the description and moving files properly implemented?** The uid (D533–D535) and
description and tags (D530–D532) are, end to end: `tests/e2e/test_documents_between_servers.py` starts two real
servers, makes a document in each app, describes it, carries the file from one server's folder to the other through
the import, and checks that the uid, description and tags arrive, that the owner opens it there with her password, that
the same document is refused a second time on a server under any name, and that a file renamed by hand is recognised
by its uid and opens for nobody. **Moving documents between places and collections by dragging is not built**: E5.18
says so, the mock-ups exist, and it waits for a decision (a page talks only to its own server, D170). **Renaming** was
reported by the owner while this ran (UX-42): the name is bound into the sealed parts; decided to bind to the uid alone
and let the owner rename (D536, story E5.21, not built). Also open from the branch's own note: description and tags are
not written into exported Office and OpenDocument files, and there is no File ▸ Properties… in the document or the
shells.
