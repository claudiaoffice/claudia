# CI/CD (GitHub Actions)

GitLab is abandoned; its leftover `.gitlab-ci.yml` was deleted on 2026-11-10.

- `docker.yml`: one image, linux/amd64 only (Scaleway takes nothing else). Smoke test = each app with `CLAUDIA_DEMO=1` answers `/api/health`.
- `deploy-demo.yml`: GHCR -> `rg.<region>.scw.cloud/<namespace>/claudia-demo:sha-<short>` -> `PATCH registry_image` + `POST .../deploy` on the Scaleway Containers API (`v1beta1`), then waits for `status=ready` and asks the demo URL. GitHub environment `demo` (optional approval). Variables/secrets are listed at the top of the file.
- Registry pruning (2026-11-15): every deployment pushed a new `sha-<short>` tag to the Scaleway registry and none was deleted, so storage (and cost) grew with each push to main. Before the push, `deploy-demo.yml` now runs `scripts/prune_registry.py` (stdlib only, tests in `tests/test_prune_registry.py`), which deletes every tag of `claudia-demo` except the one about to be pushed, the ones the demo containers run (`registry_image` from the Containers API), the newest `SCW_DEMO_KEEP_TAGS` others (default 0) and any tag sharing a digest with those (a forced tag delete removes the manifest, and so every tag of that digest). If a container or the registry cannot be asked, nothing is deleted; the step is `continue-on-error`, so pruning never blocks a deployment. Rollback does not need the old tags: a manual run copies any tag from GHCR again. Other images in the namespace are not touched.
- `deb.yml` + `packaging/debian/build-deb.sh`: layout `/opt/claudia/{python,venv,web,shell}`, launcher `/usr/bin/claudia-composes` sets `CLAUDIA_SERVER_PYTHON`, `CLAUDIA_WEB_DIR` and `PYTHONPATH`. The venv is made at its final path (not relocatable), so the build needs an empty writable `/opt/claudia`.
- `windows.yml` (2026-11-17, branch `win-installer`, D740-D745): job `installer` builds the web frontend, the client, the frozen server (PyInstaller; smoke test of the bare server) and `claudia-office-<version>-windows-x64.exe` (Inno Setup); job `test` installs it on windows-2022 and windows-2025 and checks files, shortcuts, the service, the uninstall and a window; job `release` attaches the installer to the release of a `v*` tag. Optional SignPath step, switched on by the repository variable `SIGNPATH_ORGANIZATION_ID` (D744). `deb.yml` got the same kind of test: all three windows under Xvfb, reinstall, removal. See windows-installer.md.
- Open: deploy/publish are not gated by `ci.yml` (only by the image smoke test); arm64 image; deb for creates/computes shells (only composes has a client yet); signing of the deb / an apt repository.
- Unverified Scaleway details (documentation silent): that `PATCH registry_image` is accepted on an existing container, the `status` values (`ready`/`error`), WebSocket support on the platform, how soon the registry frees the layers of deleted tags (and so when the bill drops).
